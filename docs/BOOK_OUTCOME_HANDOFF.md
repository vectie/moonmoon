# Return a completed digital outcome through Book

The study panel now provides **Send a digital outcome to Book**. This is an explicit file workflow over a completed native simulation, not an automatic submission or a claim about physical performance.

1. Import or reopen the actual completed dossier, inspect its alternatives, then save a named digital review
2. Enter the exact completed session, observation time, your interpretation and explicit explanations for all three gaps. Severity zero is an explicit absent-gap statement; it is never preselected or inferred
3. If any gap is present, supply the complete proposed capability descriptor required by Book's existing outcome contract. This is a proposal only
4. Export the outcome and retained sources. In Book's Product outcomes panel, inspect and save it, then use the existing named-human deliverable and assessment reviews
5. Download Book's disposition receipt, open it in this panel, then choose **Reopen original study** or download its exact result. Rejected and deferred outcomes remain inspectable. Unsaved work, interrupted saves and conflicting local source bytes block a switch; separately saved digital reviews remain independent

The export includes original dossier bytes (robot, terrain, source and replay context), exact selected result bytes, and the named digital review plus operator-authored interpretation. A completed rejected simulation is still a completed result and remains labeled rejected. Changed source or statements produce a distinct submission identity; unchanged repeated exports reproduce the same package. Editing or reviewing a later outcome never changes the original dossier or digital review.

The returned receipt is validated against the original source, selected result and authored interpretation. It is an unsigned historical local observation. Only Book owns its receiver decision; a digital reviewer name is evidence, and a loaded Book receipt grants no physical command, customer acceptance, cash, capability activation or automatic transport. Refresh the saved outcome in Book for current state.

Source/control tests run without a browser. `MOON_OUTCOME_PACKAGE_OUTPUT` optionally writes the tested package for the `.mbtx` integration fixture; `MOON_OUTCOME_BOOK_RECEIPT` exercises the actual Book CLI readback. These are fixture-only environment inputs. No credentials, provider calls or hardware are involved.
